# Clover Scope — 四つ葉ファインダー

スマホのカメラを1株ずつクローバーに向けると、四つ葉らしさをその場で判定します。
通信は一切ありません。判定は端末の中で完結します。

**→ https://USER.github.io/clover-finder/**

インストール不要。ホーム画面に追加すればオフラインでも動きます。

---

## 使い方

1. 「スキャン開始」→ カメラを許可
2. **枠の中に1株だけ入るまで近づく**（地面すれすれ、または摘んで手に持つ）
3. 四つ葉らしさが数字とバーで出続けます
4. 90%を4回連続で超えると音とバイブで知らせ、その場所を記録します

枠の大きさは `＋` `−` で調整。写真ファイルから調べることもできます。

---

## 正直な性能

未使用の写真75枚での検証:

| 確信度のしきい値 | 適合率 | 再現率 | 誤検出 |
|---|---|---|---|
| 0.50 | 72.7% | 89.9% | 30 |
| 0.70 | 84.9% | 69.7% | 11 |
| **0.90（既定）** | **100%** | **30.3%** | **0** |
| 0.95 | 100% | 15.7% | 0 |

**3株に2株は見逃します。** その代わり「四つ葉だ」と言ったときはほぼ当たります。
見逃しは歩けば取り返せますが、誤報が続くとアプリを信じなくなるので、
この非対称は意図的です。

### 得意・苦手

独立したテスト画像（`testdata/`）での傾向:

- **得意** — 1株が枠いっぱいに写り、背景と分かれているとき。
  石畳・デニム・砂利の上で 95〜100%、正確に株を捉えます。
- **苦手** — クローバーが密生した絨毯。株の境目が定まらず、見逃しも誤検出も出ます。

このため、画面全体を走査するのではなく **中央の照準に1株を収める** 設計にしています。
学習データの作者も「近接写真で最も良く動く」と報告しており、一致します。

## しくみ

約4.7万パラメータの畳み込みニューラルネット。96×96の切り出しを
`four` / `other` の2クラスに分類します。

```
conv3x3 3→16  + BN + ReLU + maxpool2   96 → 48
conv3x3 16→32 + BN + ReLU + maxpool2   48 → 24
conv3x3 32→48 + BN + ReLU + maxpool2   24 → 12
conv3x3 48→64 + BN + ReLU + maxpool2   12 → 6
global average pool → 64 → linear → 2
```

推論は **手書きのJavaScript**（`infer.js`、約150行）。TensorFlow.js も ONNX Runtime も
使いません。BatchNorm は書き出し時に直前の畳み込みへ畳み込んであるので、
必要な演算は conv / ReLU / maxpool / linear だけです。
PyTorch との一致は **最大誤差 6×10⁻⁸** で検証済み（`tools/export_weights.py`）。

### 学習

陰性を**同じ写真から**採るのが要点です。別の写真から採ると、
「四つ葉が写っている写真の全体的な雰囲気」で当てられてしまいます。

さらに1回目の学習後、**モデル自身を学習画像に走らせ、四つ葉でないのに
高得点を出した1,243箇所を陰性に追加して再学習**しました（hard negative mining）。
これで確信度90%での適合率が 90.3% → 100% になりました。
1回目は陰性がほぼ草と土だったため、モデルは「クローバーか否か」を学んでいて、
「3枚か4枚か」を学んでいませんでした。

```sh
sh tools/fetch_data.sh          # 学習データを取得（55MB, CC BY 4.0）
python3 tools/make_crops.py     # 切り出しを生成（画像単位で train/val 分割）
python3 tools/train.py          # 1回目
python3 tools/mine_hard.py      # 難例を採掘
python3 tools/train.py --out data/tinynet2.pt
python3 tools/export_weights.py # BN畳み込み + JSON書き出し
python3 tools/build_app.py      # 単一HTMLへインライン化
```

## うまくいかなかった手法の記録

`tools/` には、機械学習に移る前に試して**失敗した**古典的画像処理が残してあります。
同じ道を辿る人の役に立つかもしれないので消していません。

| 手法 | 結果 |
|---|---|
| 閾値で小葉を切り出しクラスタリング（`detect_ref.py`） | 陰性75% > 陽性74%。**逆相関** |
| 分水嶺法で小葉を分割（`seg2.py`） | **分割自体は成功**。密生マットでも個々の小葉を正確に囲める |
| ＋ 小葉の向きの一致（`classify2.py`） | 陰性73% vs 陽性65%。重なる |
| ＋ 株の輪郭の形 | 陰性73% vs 陽性70%。重なる |
| 葉柄への投票（`classify3.py`） | 誤検出ほぼ皆無だが**検出も皆無** |
| 葉脈の角度（`veins.py`, `veins2.py`） | 陽性50/48/43/41/40、陰性49/47/38。分離せず |

**分割は解けたが分類は解けなかった**、というのが結論です。

葉脈の角度は筋の良い考えでした。三つ葉の主脈は約120°、四つ葉は約90°間隔で
葉柄から出るので、これを測れば数えられるはずです。実際に測ると
**葉脈の軸は葉柄方向と±6°で一致**していました。信号は本物です。
外れた小葉はシロツメクサのV字白斑が主脈より優勢になって90°反転したもので、
原因も特定できました。それでも分類器に組み上げると、実写のばらつき
（白斑、遮蔽、セルの分裂と融合）を吸収するのに必要な自由度が、
無関係な小葉の集まりも通してしまいます。

`python3 tools/eval_veins2.py` などで再現できます。
