# Clover Scope — 四つ葉ファインダー

スマホのカメラを芝生に向けて歩くと、**画面全体を1秒ごとに調べて、四つ葉と判断した株に枠**を出します。
通信は一切ありません。判定は端末の中で完結します。

**→ https://kenta0514jp.github.io/clover-finder/**

インストール不要。ホーム画面に追加すればオフラインでも動きます。

---

## 使い方

1. 「スキャン開始」→ カメラを許可
2. 地面から30〜50cmで構え、**ゆっくり動かす**
3. 四つ葉と判断した株に琥珀色の枠が出ます（設定で三つ葉も淡い青灰で表示できます）
4. 枠が出たら音とバイブで知らせ、その場所を切り出して記録します

写真ファイルから調べることもできます。

---

## 正直な性能

学習に一切使っていない実写9枚（`testdata/`、四つ葉あり6枚 / なし3枚）での実測。
アプリと同じ前処理・同じ後処理を通した数字です。

| 解析解像度 | 四つ葉を見つけた枚数 | 誤検出（クローバーだが四つ葉の無い3枚） | 誤検出（クローバー以外587枚） |
|---|---|---|---|
| **416（既定）** | **6 / 6** | **0** | **2枚に1個ずつ** |
| 512 | 5 / 6 | 0 | 0 |
| 640 | 4 / 6 | 0.3 / 枚 | 3枚に1個ずつ |

確信度25%、植生ゲート0.25での値。**416が最良かつ最速**なので既定にしています。

背景写真587枚は机・部屋・舗装・苔・シダ・芝など、クローバーが写っていないもの。
これを学習に加える前の版は、同じ587枚に**19個**の誤検出を出していました
（そして机の上のモニタに82%を出しました）。

`p6` では四つ葉に枠が乗ると同時に、隣の三つ葉2株にも枠が出ます（48〜49%）。
**枠は候補です。数えるのは自分の目でお願いします。**

検証セット（375枚）での `clover-4` は AP50 **0.627** / AP50-95 **0.452**。
ただしこの数字は不当に低く出ています — 密生した写真では三つ葉を全部ラベル付けできないため、
ラベルの無い正しい検出が誤検出として数えられるからです。
**上の実写9枚の目視のほうが実態に近い**と考えてください。

## しくみ

**YOLOv8n の物体検出器**（約300万パラメータ、8.1 GFLOPs）。
`clover-3` と `clover-4` の2クラスで、三つ葉を背景ではなく**独立したクラス**として
学習しています。検出器が両者を直接区別することになり、
アプリ側でも「三つ葉と判断した株」を表示できるので、判定の誤りが目に見えます。

推論は **onnxruntime-web (WASM SIMD)**。ランタイムと重みはこのリポジトリに同梱してあり
（CDNではなく）、Service Worker がキャッシュするので電波の無い公園でも動きます。
GitHub Pages は COOP/COEP を設定しないためスレッドは使えず、`numThreads = 1` です。

各変換段階で数値の一致を確認しています:

| 段階 | 確認内容 | 結果 |
|---|---|---|
| ONNX 書き出し | onnxruntime vs PyTorch、同一入力の生テンソル | max 1.2×10⁻³ px（640px座標上、相対 2×10⁻⁶） |
| JavaScript | `detect.js` のNMSと座標復元 vs numpy 参照実装 | max **2.3×10⁻⁴ px** |

`tools/check_detect_js.py` が後者を quickjs 上で実行します。ブラウザが無くても検証できます。

### 学習

```sh
sh tools/fetch_data.sh                       # deton/detect4clover を取得
python3 tools/fetch_roboflow.py              # Roboflow の2データセット（要APIキー）
python3 tools/fetch_bg.py                    # クローバーの無い背景写真をWikimediaから
python3 tools/build_yolo.py                  # 統合（train 2,655+背景499 / val 287+88枚）
sh tools/train_yolo.sh                       # YOLOv8n を120エポック（GPUで22分）
python3 tools/eval_yolo.py --out sheet.png   # testdata/ で枠の位置を目視
python3 tools/export_onnx.py                 # ONNX化 + PyTorchとの一致検証
python3 tools/check_detect_js.py             # JS側の一致検証 + ブラウザ前処理での実測
python3 tools/build_app.py                   # 単一HTMLへ組み立て
```

回転増幅（`degrees=180`）を入れてあります。四つ葉は90°、三つ葉は120°対称なので、
向きの癖が手がかりになってはいけません。

**ラベルの無い背景写真499枚**が入っています。Ultralytics はラベルの無い画像を
「ここには何も無い」という教師信号として扱います。これが無かった最初の版は、
学習画像が全部クローバーだったため「四つ葉でない」と答える理由を学んでおらず、
机に向けるとモニタに82%、ノートに88%を出しました。**対象が写っていない写真は、
対象が写っている写真と同じくらい必要です。**

補助として、枠の中の緑（excess green）が25%未満なら捨てる植生ゲートを
アプリ側に入れてあります（`detect.js` の `vegFrac`）。四つ葉は緑の植物なので、
植生の無い枠はスコアが何%でも誤りです。

APIキーは会話やコマンドラインに残さないため `~/.roboflow_key` から読みます。

## うまくいかなかった手法の記録

`tools/` には、ここに至るまでに試して**失敗した**手法が残してあります。
同じ道を辿る人の役に立つかもしれないので消していません。

| 手法 | 結果 |
|---|---|
| 閾値で小葉を切り出しクラスタリング（`detect_ref.py`） | 陰性75% > 陽性74%。**逆相関** |
| 分水嶺法で小葉を分割（`seg2.py`） | **分割自体は成功**。密生マットでも個々の小葉を正確に囲める |
| ＋ 小葉の向きの一致（`classify2.py`） | 陰性73% vs 陽性65%。重なる |
| ＋ 株の輪郭の形 | 陰性73% vs 陽性70%。重なる |
| 葉柄への投票（`classify3.py`） | 誤検出ほぼ皆無だが**検出も皆無** |
| 葉脈の角度（`veins.py`, `veins2.py`） | 陽性50/48/43/41/40、陰性49/47/38。分離せず |
| **小型CNNの分類器を全画面に滑らせる**（`infer.js`, `dense.py`） | 切り出しの判定は93%適合率。**しかし枠の位置が当てにならない** |
| ＋ 中心ずれ窓を陰性に追加（`make_offcenter.py`） | 適合率 93.2%→**60.0%**、再現率 50.5%→**1.0%**。崩壊 |

**分割は解けたが分類は解けなかった**、というのが古典的手法の結論でした。

葉脈の角度は筋の良い考えでした。三つ葉の主脈は約120°、四つ葉は約90°間隔で
葉柄から出るので、これを測れば数えられるはずです。実際に測ると
**葉脈の軸は葉柄方向と±6°で一致**していました。信号は本物です。
それでも分類器に組み上げると、実写のばらつき（白斑、遮蔽、セルの分裂と融合）を
吸収するのに必要な自由度が、無関係な小葉の集まりも通してしまいます。

### 分類器を検出器の代わりにしてはいけない

いちばん高くついた失敗です。
96×96の切り出しを分類する小型CNNを作り、全結合層を1×1畳み込みとして扱って
画面全体に一度で畳み込みました（fully-convolutional、窓ごとに回すより約36倍速く、
結果が厳密に一致することも検証済み）。速度は解決しました。**位置は解決しませんでした。**

分類器には**位置損失がありません**。さらに学習データが「対象の中心に置かれた切り出し」
ばかりだったため、**対象を半分だけ捉えた窓を一度も見ていません**。
密走査が実際に当たるのはそういう窓です。結果、四つ葉の**下の石畳**に95%が出ました。

安価な修正も試しました。四つ葉を窓の端に追いやった切り出し5,138枚を陰性に足して
再学習すると、**分類器は崩壊しました**（確信度0.90で適合率 93.2%→60.0%、
再現率 50.5%→1.0%）。中心ずれの窓は分類器から見て陽性とほとんど区別が付かず、
押し込もうとすると陽性側まで巻き添えになります。位置損失なしにこれは教えられない、
というのがこの実験の結論です。

物体検出器に替えると、同じデータ・同じ写真で枠が株に吸い付きました。
位置回帰と物体性スコアを直接学習していることが本質的な差です。

この一式（`infer.js` と密走査）は削除せず、ランタイムを取得できない端末向けの
代替として、また記録として残してあります。アプリはその場合
「簡易判定で動作中 — 枠の位置は当てになりません」と表示します。

なお、この過程で得た手順は Claude のスキル `mobile-detector-app` にまとめてあります。
